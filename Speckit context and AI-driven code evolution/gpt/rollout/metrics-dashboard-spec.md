# AI Adoption Metrics Dashboard Spec

Source constraint: this dashboard spec is produced from `info.md` only.

## Purpose

Measure whether the team is moving from casual AI usage toward serious, governed, reusable AI-assisted engineering.

## Maturity Metrics

| Metric | Why It Matters |
| --- | --- |
| Markdown artifacts created | Shows knowledge capture is happening |
| Diagrams created and reviewed | Shows shared architecture understanding |
| Agent transcripts logged | Shows reasoning is preserved |
| Repeated prompts converted to workflows | Shows movement away from ad hoc prompting |
| Workflows promoted to skills | Shows reusable capability is emerging |
| Skills promoted to GPT gems | Shows enterprise patterns are being packaged |
| Evidence packs completed | Shows governance and traceability |
| Decision records created | Shows important choices are explicit |

## Quality Metrics

| Metric | Target Behavior |
| --- | --- |
| Percentage of artifacts with source context | AI output remains grounded |
| Percentage of diagrams reviewed | Visuals remain useful and accurate |
| Percentage of high-impact outputs with human review | Governance keeps pace |
| Number of unsupported claims removed | Quality improves over time |
| Number of reusable workflows adopted by more than one team | Practices scale beyond individuals |

## Adoption Signals

- Engineers use workflows without needing custom prompting each time.
- Architecture discussions reference diagrams and markdown artifacts.
- Governance review is based on evidence packs, not scattered chat history.
- GPT gems represent proven practice rather than experiments.
- The roadmap becomes a living playbook.
