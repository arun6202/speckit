# Pandoc Publishing Guide

Source constraint: this guide is produced from `info.md` only.

## Purpose

Markdown should remain the working format for AI adoption artifacts. Pandoc can be used when the team needs shareable documents for architecture reviews, onboarding, leadership communication, or enterprise governance.

## Recommended Inputs

- Brownfield discovery notes
- Agent transcript logs
- Architecture markdown
- Mermaid, C4, and CLLA diagram sources
- Decision records
- Governance checklists
- Risk register
- GPT gems catalog

## Publishing Rules

1. Keep source markdown as the canonical artifact.
2. Do not publish unresolved assumptions as confirmed facts.
3. Keep diagrams as source text whenever possible.
4. Include transcript and decision record references.
5. Keep output documents versioned with the source artifacts.

## Suggested Document Types

| Document | Source Artifact |
| --- | --- |
| AI Adoption Playbook | `brownfield-ai-adoption-bible.md` |
| Roadmap Briefing | `ai-adoption-roadmap.jsx` plus roadmap notes |
| Governance Pack | Checklist, risk register, evidence packs |
| Architecture Pack | C4, CLLA, Mermaid, decision records |
| Skills and Gems Catalog | Skill candidates and GPT gems |

## Export Checklist

- [ ] Source markdown reviewed
- [ ] Diagrams reviewed
- [ ] Assumptions marked
- [ ] Decision records linked
- [ ] Governance notes included
- [ ] Published output stored next to source or in a known publishing location
