Three-Layer Architecture

A/1
SKLSkills Reusable domain expertise — teach how to do a task well. Passive, composable, single canonical source.
loads on demand ↑
AGTAgents Workflow orchestrators with identity — decide what to do, when, and in what order. Own persona, deliverables, guardrails.
reads through ↑
MCPMCP Connectors Standardized data-access layer — connect to external systems. Keep connection logic out of agents and skills; swappable, centrally managed.
▣ Separation of concerns lets each layer evolve independently.

Redline · skill semantics

“Stay passive” is a useful heuristic, not a hard rule — Skills legitimately bundle scripts and can encode internal sequencing. Note also that slash commands are a Claude Code / Claude.ai surface feature, distinct from Skills; the panel conflates two primitives.

04

Tiered Isolation

S/1

Reader

  • Touches untrusted documents
  • Read + grep only
  • No MCP, no write tools

Orchestrator

  • Never reads outsider files directly
  • Coordinates workflow
  • Trusted read-only MCP

Critic

  • Independently verifies findings
  • Adjudicates before write

Resolver

  • Creates final output artifacts
  • Write access only
  • No outsider files, no MCP
🔒 Deny tools by default. Grant only the minimum needed.
Redline · pattern lineage

The architecture is sound, but the role names are this author’s branding — not standard nomenclature. The Reader↔Orchestrator split is the dual-LLM / quarantined-LLM pattern (Willison, 2023): a privileged model holds tools but never reads untrusted text. “Critic” = the LLM-as-judge / guardrail layer; “reader ≠ actor” separation is documented practice. See CaMeL for the formal version.

Redline · transport security

Add the controls the panel omits: for any network-exposed server, the June 2025 spec mandates OAuth 2.1 with token-audience separation. Treat token passthrough as an explicit anti-pattern — it breaks trust boundaries and makes authorization unauditable. Tag trust level at the transport layer, not in prompt text.
