1. Overview

The tool answers one question: if I send this prompt to Windsurf using a given Claude model, roughly how many credits will it cost? It exists because Windsurf meters third-party models (Claude, GPT) by token consumption, so the cost of a prompt is invisible until after it runs. Pasting the prompt here gives a defensible estimate up front.

Everything reduces to tokens. The pasted text is converted to an input-token estimate; output and (optionally) thinking tokens are predicted from that input via adjustable assumptions; each token class is priced at a per-model credit rate; and the result is shown as a band, because output length is never known exactly before generation.

The design philosophy is honesty about uncertainty: input is the only quantity that is close to measured. Everything else — output length, thinking budget, and the size of an agent loop — is a prediction you calibrate. The numbers are a planning instrument, not a billing meter.

2. Quick start

  1. Open windsurf-credit-xray.html in any browser. Nothing is installed; nothing leaves the page.
  2. Paste your prompt, spec, file, or context into the large box. The character, word, line, and base-token counts update live.
  3. Pick a Task — this sets the output-expansion band (W).
  4. Pick a Claude model — this sets the credit rate, tokenizer density, context/output caps, and whether thinking tokens are billed.
  5. Read the hero band: low / expected / high credits for that prompt.
  6. (Optional) For real Cascade work, open the Agentic Loop panel and set the number of turns — the estimate becomes a session total.
  7. Tune any parameter below (chars/token, W, thinking budget, overhead, credit rates, budget) to match your situation.

Press Esc or the Clear button to empty the input.

3. The credit model — how tokens become credits

Windsurf bills external models (Claude, GPT) on a token basis with a margin:

credits = tokens × model-multiplier + ~20% margin

A credit is worth roughly $0.04, derived from the add-on pack price of $10 per 250 credits. Combining the margin and the credit price gives a single conversion from API dollars to credits:

credits = API-dollar-cost × 1.20 ÷ $0.04 = API-dollar-cost × 30

Verification against Windsurf's own published example. A single complex task on Sonnet using 10M tokens (5M input + 5M output) is documented as ≈ 2,700 credits:

API cost   = 5M × $3/1M (in) + 5M × $15/1M (out) = $15 + $75 = $90
+ 20% margin                                      = $108
÷ $0.04 per credit                                = 2,700 credits   ✓

This reproduces the published figure exactly, which is why the per-model credit rates below are trustworthy defaults.

Per-1M-token credit rates (margin already included):

Tier API $/1M (in / out) Credit rate (in / out)
Opus $5 / $25 150 / 750 cr
Sonnet $3 / $15 90 / 450 cr
Haiku $1 / $5 30 / 150 cr

Output bills at exactly 5× input on every current Claude tier, so the output rate is always five times the input rate.

Important context shift. Windsurf retired its monthly credit pool on 19 March 2026 and moved to daily/weekly quotas. Under the new system these credit rates are what your overage consumes once the quota is exhausted; subscribers from before that date are grandfathered on the old pool. Either way, the token→credit math above is the right unit of account, which is why the tool speaks entirely in credits.

Thinking variants share the per-token rate of their base model. The only difference is that they emit reasoning tokens, which bill at the output rate. That is why a "Thinking" model can cost a multiple of its plain twin on the same prompt.

5. The token-economics model

A prompt's cost is the sum of three token classes:

  • Input — what you paste, plus per-call overhead (system prompt + tool schemas). Billed at the input rate.
  • Thinking — reasoning tokens, present only on Thinking models. Billed at the output rate.
  • Output — the model's reply. Billed at the output rate.

Output is modelled as a multiple of input: output_tokens = input_tokens × W, where W is a task-dependent expansion ratio. The Task dropdown prefills a low/typical/high band:

Task W (low · typ · high)
Summarize / extract / classify 0.05 · 0.1 · 0.25
Q&A / explain 0.2 · 0.4 · 1.0
Translate / reformat 0.9 · 1.0 · 1.2
Refactor / edit a file 0.9 · 1.1 · 1.5
Generate code from a spec 1 · 2 · 4
Expand outline → full doc 3 · 5 · 10

Why W dominates the bill. Because the output rate is 5× the input rate, the per-prompt cost simplifies to:

cost ≈ input_tokens × input_rate × (1 + 5·W)

So W = 0.2 doubles the input-only cost; W = 1 makes it six times; W = 2, eleven times. On any generative task the output term carries most of the credits — which is exactly why a tool that only counted input would mislead.

Tokenizer density (×). The generic token estimate (characters ÷ ratio) is tokenizer-agnostic. A per-model density factor corrects it: the Opus 4.7 generation introduced a tokenizer that produces up to ~35% more tokens for the same text than 4.6, carried into 4.8. The default is 1.25 for 4.7/4.8 and 1.0 for 4.6 and Haiku. Same price per token, but more tokens — so Opus 4.8 costs more credits than Opus 4.6 on identical input, a trap the comparison strip makes visible.

Per-call overhead. Cascade ships a system prompt and tool-schema definitions on every call. This is real input that most estimates omit; it is added to the pasted input on each turn (default ≈ 1,500 tokens).

6. The agentic loop (session cost)

A single Cascade prompt is rarely one model call. The agent reads files, writes code, runs tests, and reasons over several turns, and each turn re-sends the accumulated conversation. This is the largest source of real-world cost and the main thing naïve estimates miss.

The Agentic Loop panel models it with two inputs — number of turns N and tool-result tokens added per turn T — plus an optional caching toggle. When N = 1 the result equals a single prompt; raising N turns the estimate into a session total.

The math. Let baseIn be the turn-1 input (pasted input + overhead, adjusted by density), outPer the per-turn output, thPer the per-turn thinking, and toolAdd the per-turn tool tokens. Across N turns the re-sent context accumulates, so total input carries a quadratic term:

input_tokens (no cache) = baseIn × N + (outPer + toolAdd) × N(N−1)/2
output_tokens           = outPer × N
thinking_tokens         = thPer × N

The N(N−1)/2 factor is why a 10-turn session costs far more than 10× a single prompt — often 20–40× once accumulation dominates. The Loop amplification metric reports this multiple directly.

Caching. In a loop the re-sent prefix (system prompt, tool schemas, earlier context) is largely identical turn to turn. Prompt caching bills that re-sent portion at ~10% of the input rate. With caching on, the tool charges the first send in full and everything re-sent afterward at 10%:

input_tokens (cache) = baseIn + 0.1 × [ (N−1)·baseIn + (outPer + toolAdd)·N(N−1)/2 ]

This is the single biggest lever for keeping a long agent loop affordable. It is flagged as conditional because it is uncertain whether Windsurf passes API-level caching through to credit billing — treat it as a best case.

Context footprint is per-turn, not cumulative. A session never holds all turns in the window at once; only the busiest (last) turn must fit. The tool therefore checks the peak-turn footprint — peak-turn input + output + thinking — against the model's context window (1M for Opus/Sonnet, 200K for Haiku), and against the one-turn generation cap (128K, or 64K for Haiku).

7. Parameters reference

Every parameter is editable; the dropdowns prefill sensible defaults.

8. Readouts reference

  • Hero band — low / expected / high credits for the prompt (or session when N > 1). The marker shows where "expected" sits within the range; the spread comes from W and the thinking band varying.
  • Breakdown — input / thinking / output as tokens and credits, plus a total. With caching in a session, the input credits reflect the discount (marked *).
  • Credit composition — share of credits by class. On generative tasks output dominates.
  • Token composition — share of tokens by class.
  • Context footprint — peak-turn tokens against the model's context window, with a 200K marker and warnings for window or generation-cap overflow.
  • Credits / turn (avg) — session total ÷ N.
  • Loop amplification — session cost ÷ single-prompt cost; the agent-loop multiplier.
  • Output share of credits — fraction of credits spent generating (thinking + output).
  • Budget context — this run as a percent of the budget, how many runs the budget buys, and how many fit a 250-credit add-on pack.
  • Model comparison — expected credits across the full lineup for the same input, task, and loop; bars relative to the priciest. Note 4.8 > 4.6 within a tier, from density alone.

9. Estimation accuracy & calibration

The input estimate (characters ÷ ratio, then × density) is typically within ~10–20% of a true tokenizer count for mixed content. That is adequate for "know the cost before prompting," and the ratio is exposed so you can calibrate it.

To turn the bands from plausible into trustworthy, pull a few real runs from your Windsurf usage history and back out the actual numbers: the true output:input ratio (set W), a representative thinking budget, and — for Cascade — the real turn count and per-turn tool tokens. After one calibration pass the expected column tracks reality closely.

The expected value is the column to trust; the low/high endpoints assume W (and thinking) move together, so they intentionally bracket a wide plausible range rather than a statistical confidence interval.

10. Assumptions & caveats

  • Ballpark, not a meter. Input is near-measured; output, thinking, and loop size are predictions. The tool never sees actual generation.
  • Credit basis. Defaults assume a $0.04 credit (the $10 / 250 add-on pack) and Windsurf's ~20% external-model margin. Both are folded into the per-model credit rates and can be edited.
  • Quota era. Windsurf moved from a monthly credit pool to daily/weekly quotas in March 2026; the credit rates here are what overage consumes. Quota percentages in the Windsurf UI are opaque and not modelled directly — the budget panel uses a pool framing for intuition.
  • Caching is conditional. The −90% on re-sent context applies only if Windsurf passes API caching through to credit billing, which is unconfirmed. Treat caching-on as a best case.
  • Projected Sonnet. Sonnet 4.7/4.8 are not released as of June 2026; they are included at Sonnet's tier rate with 4.7-generation density as a forward-looking convenience.
  • Loop model is a simplification. Linear context growth per turn with a quadratic accumulation term captures the right shape; real Cascade behavior varies with tool use, retries (failed operations don't consume quota), and summarization/compaction.
  • SWE / proprietary models excluded by design — they consume 0 credits.
  • Tab autocomplete is free on all Windsurf plans and is not part of this estimate.

11. Formula reference

base_input      = characters / chars_per_token
effective input = (base_input + overhead) × density          # turn-1 input, model tokens
output_per_turn = base_input × W × density
thinking_per_turn = (thinking ? thinking_budget : 0) × density
tool_add        = tool_tokens_per_turn × density

# session over N turns
input_tokens  = effective_input × N + (output_per_turn + tool_add) × N(N−1)/2
  (cache on)  = effective_input + 0.1 × [ (N−1)·effective_input + (output_per_turn + tool_add)·N(N−1)/2 ]
output_tokens = output_per_turn × N
think_tokens  = thinking_per_turn × N

# credits  (rate units: credits per 1,000,000 tokens; output_rate = 5 × input_rate)
input_credits  = input_tokens  × input_rate  / 1e6
think_credits  = think_tokens  × output_rate / 1e6
output_credits = output_tokens × output_rate / 1e6
total_credits  = input_credits + think_credits + output_credits

# single-prompt shortcut (N = 1, no tools/cache)
total ≈ effective_input × input_rate/1e6 × (1 + 5·W)   + thinking term

# peak-turn context footprint
peak = [effective_input + (N−1)(output_per_turn + tool_add)] + output_per_turn + thinking_per_turn

# dollars → credits (basis for the default rates)
credits = usd_cost × 1.20 / 0.04 = usd_cost × 30

12. Technical notes

The tool is a single HTML file with inline CSS and vanilla JavaScript — no frameworks, no external requests, no fonts or libraries fetched, no analytics. It runs fully offline and stores nothing (no cookies, no localStorage); refreshing resets it. Typography uses a monospace system stack (Cascadia Code, JetBrains Mono, SF Mono, Consolas, …) for the engineering-instrument aesthetic, falling back gracefully. It is responsive down to phone width. All computation is client-side and recomputes live on any input change.
