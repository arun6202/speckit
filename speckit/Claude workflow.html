Context Flow Blueprint — rules · workflows · skills · memories

How global & repo artifacts are READ into the context window each turn, and the two kinds of WRITE that close the loop. First-class primitives: Rules / Workflows / Memories. Skills = on-demand SKILL.md layer on top.

READ — context assembled in WRITE · ephemeral — memory, local, free WRITE · durable — rule/AGENTS.md, committed

Gotcha: Memories are workspace-scoped and machine-local — never committed, never auto-synced to teammates. Anything that must travel with the team goes in a Rule or AGENTS.md, not a memory.

Read → Write cycle (the "write-write" = dual write)

every turn can emit two distinct writes

  subgraph R["① READ — assemble context"]
    direction TB
    R1["global rules — always"]:::read
    R2["repo rules — per activation mode"]:::read
    R3["memories — relevance retrieval"]:::read
    R4["skills — model-decision load"]:::read
    R5["workflow steps — only if /invoked"]:::read
  end

  R --> X["② EXEC
plan → tool calls → diff-staged edits"]:::exec

  X --> W

  subgraph W["③ WRITE-BACK — two channels"]
    direction TB
    WA["EPHEMERAL · local · free
auto-memory  +  'create a memory of…'"]:::eph
    WD["DURABLE · committed
edit rule / workflow / AGENTS.md"]:::dur
  end

  WA -.->|feeds retrieval| R3
  WD -.->|feeds next assembly| R2
  W  ==>|turn N+1| P
The two writes: ephemeral closes the loop automatically (memory → next-turn retrieval, zero credits, dies with the machine). durable is the promotion path — you graduate a learned memory into a committed rule so it survives, shares, and applies deterministically.
